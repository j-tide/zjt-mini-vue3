# 01_编译模块概述

### 一、template为什么需要编译

浏览器最终执行的是`JavaScript`，而我们在`.vue`文件中更习惯写：

```vue
<div>hi, {{ message }}</div>
```

这段`template`本身不能直接作为运行时的渲染逻辑执行，所以需要先把它编译成类似下面这样的`render`函数：

```ts
function render(_ctx, _cache) {
  return _createElementVNode(
    'div',
    null,
    'hi, ' + _toDisplayString(_ctx.message)
  );
}
```

这里的`_createElementVNode`和`_toDisplayString`都是运行时提供的函数。也就是说，编译器主要负责“把模板翻译成函数调用”，而真正创建节点、更新节点的工作仍然由`runtime`完成。

### 二、compiler相关模块的分工

在Vue源码中，编译相关能力不是全部放在一个包里：

1. `compiler-sfc`负责解析`.vue`单文件组件，把`template`、`script`和`style`等部分拆出来；
2. `compiler-dom`在`compiler-core`的基础上补充浏览器相关的编译能力；
3. `compiler-core`负责通用的模板解析、转换和代码生成；
4. `runtime-core`和`runtime-dom`负责执行编译生成的`render`函数。

当前这个`mini-vue`主要实现的是`compiler-core`的`happy path`，支持插值、element、text，以及把简单模板编译成运行时可以执行的`render`函数。

### 三、编译流程

当前实现的入口是`baseCompile`：

```ts
export function baseCompile(template: string) {
  const ast = baseParse(template);

  transform(ast, {
    nodeTransforms: [
      transformsExpression,
      transformElement,
      transformText
    ]
  });

  return generate(ast);
}
```

可以把它拆成三步：

```text
template字符串
      ↓
baseParse
      ↓
AST
      ↓
transform
      ↓
带有codegen信息的AST
      ↓
generate
      ↓
render函数代码
```

#### 1. parse

`parse`负责识别输入字符串中的三种基础节点：

- `{{ message }}` -> `INTERPOLATION`
- `<div></div>` -> `ELEMENT`
- `hello` -> `TEXT`

它只关注语法结构，不直接生成JavaScript代码。

#### 2. transform

`transform`采用插件的形式遍历AST。不同插件处理不同的需求：

- `transformsExpression`给插值表达式加上`_ctx.`；
- `transformElement`把element转换成VNode调用信息；
- `transformText`把相邻的文本和插值合并成复合表达式。

同时，transform还会收集当前模板需要的运行时helper。

#### 3. codegen

`generate`根据AST节点类型生成JavaScript字符串，并在函数前面解构需要的helper：

```ts
const { toDisplayString: _toDisplayString } = Vue
return function render (_ctx, _cache) {
  return _toDisplayString(_ctx.message)
}
```

这里的`Vue`不是浏览器中的全局对象，而是在运行时生成函数时传入的对象。

### 四、compiler和runtime是怎么接上的

`packages/vue/src/index.ts`中把`compiler-core`和`runtime-dom`连接了起来：

```ts
function compilerToFunction(template) {
  const { code } = baseCompile(template);
  const render = new Function('Vue', code)(runtimeDom);
  return render;
}

registerRuntimeCompiler(compilerToFunction);
```

组件初始化时，如果组件没有直接提供`render`，但提供了`template`，`runtime-core`会调用刚刚注册的编译器：

```ts
if (compiler && !Component.render) {
  if (Component.template) {
    Component.render = compiler(Component.template);
  }
}
```

所以，`template`并不是在每次更新时都重新解析，而是在组件完成初始化时被编译成`render`函数，之后交给运行时的响应式更新流程。

### 五、当前实现的边界

当前版本是为了学习Vue源码主流程，优先完成`happy path`，暂时没有实现：

- 属性和指令的完整解析；
- 注释、自闭合标签和更多HTML边界；
- `v-if`、`v-for`等指令转换；
- 静态提升、缓存和patch flag优化；
- 完整的表达式解析和错误恢复。

这些能力并不影响我们理解最核心的链路：先解析出树，再转换树，最后把树生成成运行时函数调用。
