# 03_实现组件通信和插槽

### 一、组件之间为什么需要通信

组件拆分以后，父组件和子组件通常需要完成两件事情：

1. 父组件把数据传给子组件；
2. 子组件把事件通知给父组件。

在当前的mini-vue中，这两条链路分别由`props`和`emit`实现。除此以外，组件还可以通过`slots`接收父组件传进来的内容。

### 二、初始化props

父组件创建子组件`vnode`时，可以把数据放到第二个参数：

```ts
h(Child, {
  msg: 'hello',
  onChange: changeChildProps
});
```

创建组件实例时，`setupComponent`会先初始化props：

```ts
export function setupComponent(instance) {
  initProps(instance, instance.vnode.props);
  initSlots(instance, instance.vnode.children);

  setupStatefulComponent(instance);
}
```

当前`initProps`的实现非常直接：

```ts
export function initProps(instance, rawProps) {
  instance.props = rawProps || {};
}
```

也就是说，组件`vnode`上的`props`会被保存到组件实例的`props`字段里。

在`setup`中可以直接拿到它：

```ts
const Child = {
  setup(props) {
    console.log(props.msg);
  },

  render() {
    return h('div', {}, this.$props.msg);
  }
};
```

运行时传给`setup`的props是`shallowReadonly`：

```ts
const setupResult = setup(
  shallowReadonly(instance.props),
  { emit: instance.emit }
);
```

这样做的目的不是阻止读取，而是避免子组件直接修改父组件传进来的数据。

### 三、组件代理如何读取props

除了通过`setup(props)`读取，render函数还可以写`this.msg`。这是因为公共代理会先检查`setupState`，再检查`props`：

```ts
get({ _: instance }, key) {
  const { setupState, props } = instance;

  if (hasOwn(setupState, key)) {
    return setupState[key];
  } else if (hasOwn(props, key)) {
    return props[key];
  }
}
```

所以可以简单理解为：

```text
this.xxx
  -> setupState.xxx
  -> props.xxx
  -> $el / $slots / $props
```

如果字段名同时存在于`setupState`和`props`，当前实现会优先返回`setupState`。

### 四、emit的实现

子组件通知父组件时，可以调用：

```ts
const Child = {
  setup(props, { emit }) {
    function add() {
      emit('add-foo', 1);
    }

    return {
      add
    };
  },

  render() {
    return h('button', { onClick: this.add }, 'add');
  }
};
```

父组件通过`onAddFoo`接收：

```ts
h(Child, {
  onAddFoo(value) {
    console.log(value);
  }
});
```

`emit`的关键是把事件名转换成props中对应的处理函数名：

```ts
export function emit(instance, event, ...args) {
  const { props } = instance;

  const handlerName = toHandlerKey(camelize(event));
  const handler = props[handlerName];
  handler && handler(...args);
}
```

转换过程是：

```text
add-foo
  -> camelize
addFoo
  -> toHandlerKey
onAddFoo
```

这里体现了一个很实用的实现习惯：先针对一个具体场景把链路跑通，再把字符串转换抽成通用工具函数。

### 五、slot的基本用法

父组件可以把一段vnode内容作为第三个参数传给子组件：

```ts
h(Foo, {}, {
  default: h('p', {}, 'foo: 单节点')
});
```

也可以传多个节点：

```ts
h(Foo, {}, {
  default: [
    h('p', {}, 'foo: 多节点1'),
    h('p', {}, 'foo: 多节点2')
  ]
});
```

在`createVNode`中，如果当前节点是组件，并且`children`是对象，就会增加`SLOT_CHILDREN`标识：

```ts
if (vnode.shapeFlag & ShapeFlags.STATEFUL_COMPONENT) {
  if (isObject(children)) {
    vnode.shapeFlag |= ShapeFlags.SLOT_CHILDREN;
  }
}
```

接着`initSlots`只处理带有这个标识的组件：

```ts
export function initSlots(instance, children) {
  const { vnode } = instance;
  if (vnode.shapeFlag & ShapeFlags.SLOT_CHILDREN) {
    normalizeObjectSlot(children, instance.slots);
  }
}
```

### 六、normalize把slot统一成数组

`normalizeObjectSlot`会遍历父组件传进来的插槽对象：

```ts
function normalizeObjectSlot(children, slots) {
  for (const key in children) {
    const value = children[key];
    slots[key] = isFunction(value)
      ? props => normalizeSlotValue(value(props))
      : normalizeSlotValue(value);
  }
}

function normalizeSlotValue(value) {
  return isArray(value) ? value : [value];
}
```

这段代码做了两件事情：

1. 单个vnode被转换成数组；
2. 如果slot本身是函数，则保留函数形式，并在调用后把结果转换成数组。

统一成数组以后，子组件就不需要分别处理“单节点插槽”和“多节点插槽”。

### 七、具名插槽和作用域插槽

具名插槽只是把`default`换成其它名字：

```ts
h(Foo3, {}, {
  header: h('p', {}, 'foo: header'),
  footer: h('p', {}, 'foo: footer')
});
```

子组件通过名字读取：

```ts
render() {
  return h('div', {}, [
    renderSlots(this.$slots, 'header'),
    renderSlots(this.$slots, 'footer')
  ]);
}
```

作用域插槽则传入一个函数，子组件渲染时把自己的数据作为参数传回去：

```ts
h(Foo4, {}, {
  header: ({ age }) => h('p', {}, 'age: ' + age)
});
```

`renderSlots`会根据slot是函数还是数组，分别调用：

```ts
export function renderSlots(slots, name, props) {
  const slot = slots[name];

  if (slot) {
    if (isFunction(slot)) {
      return createVNode(Fragment, {}, slot(props));
    } else {
      return createVNode(Fragment, {}, slot);
    }
  }
}
```

### 八、为什么需要Fragment

插槽可能返回多个vnode，但组件render函数通常需要返回一个根vnode。这里用`Fragment`包住多个子节点：

```ts
export const Fragment = Symbol('Fragment');
```

`patch`遇到`Fragment`时不创建额外的真实元素，只渲染它的children：

```ts
function processFragment(n1, n2, container, parentComponent, anchor) {
  mountChildren(n2.children, container, parentComponent, anchor);
}
```

所以`Fragment`是一个运行时控制节点，不会在页面上多出一层DOM。

### 九、Text节点

除了普通元素和组件，运行时还需要表示单独的文本节点：

```ts
export const Text = Symbol('Text');

export function createTextVNode(text: string) {
  return createVNode(Text, {}, text);
}
```

当`patch`遇到`Text`时，当前实现会创建浏览器文本节点：

```ts
function processText(n1, n2, container) {
  const { children } = n2;
  const textNode = (n2.el = document.createTextNode(children));
  container.append(textNode);
}
```

这样，在插槽或多个子节点场景中，普通字符串也可以被明确表示为一个vnode。

### end

现在，组件已经具备了基础的输入输出能力：

```text
父组件 --props--> 子组件
子组件 --emit--> 父组件
父组件 --slots--> 子组件
```
