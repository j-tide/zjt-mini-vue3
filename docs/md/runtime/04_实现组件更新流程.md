# 04_实现组件更新流程

### 一、更新从哪里开始

初始化时，组件的render函数会被包在一个响应式effect里：

```ts
instance.update = effect(() => {
  // 初始化或更新
});
```

因此，render函数里读取到的响应式数据会被reactivity模块收集。当数据发生变化时，effect就会再次执行，组件生成新的子树，运行时再拿新旧子树做patch。

可以把这条链路先记成：

```text
响应式数据变化
      ↓
组件effect被触发
      ↓
生成新的subTree
      ↓
patch(prevSubTree, subTree)
      ↓
更新真实节点
```

### 二、setupRenderEffect区分初始化和更新

当前实现使用`instance.isMounted`区分两种情况：

```ts
function setupRenderEffect(instance, initialVnode, container, anchor) {
  instance.update = effect(() => {
    if (!instance.isMounted) {
      const { proxy } = instance;
      const subTree = (instance.subTree =
        instance.render.call(proxy, proxy));

      patch(null, subTree, container, instance, anchor);

      initialVnode.el = subTree.el;
      instance.isMounted = true;
    } else {
      const { vnode, next } = instance;

      if (next) {
        next.el = vnode.el;
        updateComponentPreRender(instance, next);
      }

      const { proxy } = instance;
      const subTree = instance.render.call(proxy, proxy);
      const prevSubTree = instance.subTree;
      instance.subTree = subTree;

      patch(prevSubTree, subTree, container, instance, anchor);
    }
  }, {
    scheduler() {
      queueJobs(instance.update);
    }
  });
}
```

初始化阶段：

1. 执行render得到第一个`subTree`；
2. 用`patch(null, subTree)`创建真实节点；
3. 保存`instance.subTree`和根节点`el`；
4. 把`isMounted`改成`true`。

更新阶段：

1. 执行render得到新的`subTree`；
2. 保存旧的`prevSubTree`；
3. 用新旧子树调用`patch`；
4. 由patch决定哪些节点可以复用，哪些节点需要更新、创建或删除。

### 三、组件props更新

如果父组件重新render，并且子组件的props发生变化，patch会再次进入`processComponent`：

```ts
function processComponent(n1, n2, container, parentComponent, anchor) {
  if (n1 == null) {
    mountComponent(n2, container, parentComponent, anchor);
  } else {
    updateComponent(n1, n2);
  }
}
```

`updateComponent`不会直接重新创建子组件，而是复用旧的组件实例：

```ts
function updateComponent(n1, n2) {
  const instance = (n2.component = n1.component);

  if (shouldUpdateComponent(n1, n2)) {
    instance.next = n2;
    instance.update();
  } else {
    n2.el = n1.el;
    instance.vnode = n2;
  }
}
```

`shouldUpdateComponent`当前通过对比新props判断是否需要更新：

```ts
export function shouldUpdateComponent(prevVNode, nextVNode) {
  const { props: prevProps } = prevVNode;
  const { props: nextProps } = nextVNode;

  for (const key in nextProps) {
    if (nextProps[key] !== prevProps[key]) {
      return true;
    }
  }

  return false;
}
```

需要更新时，先把新的vnode暂存在`instance.next`，然后执行组件自己的更新runner。runner进入更新分支后，调用`updateComponentPreRender`：

```ts
function updateComponentPreRender(instance, nextVNode) {
  instance.vnode = nextVNode;
  instance.next = null;
  instance.props = nextVNode.props;
}
```

这样，子组件下一次render读取`this.msg`时，代理拿到的就是新的props。

### 四、patchElement复用旧元素

元素更新时，`processElement`会从初始化分支切换到更新分支：

```ts
function processElement(n1, n2, container, parentComponent, anchor) {
  if (!n1) {
    mountElement(n2, container, parentComponent, anchor);
  } else {
    patchElement(n1, n2, container, parentComponent, anchor);
  }
}
```

`patchElement`不会重新创建DOM，而是先复用旧节点：

```ts
function patchElement(n1, n2, container, parentComponent, anchor) {
  const oldProps = n1.props || EMPTY_OBJ;
  const newProps = n2.props || EMPTY_OBJ;

  const el = (n2.el = n1.el);

  patchChildren(n1, n2, el, parentComponent, anchor);
  patchProps(el, oldProps, newProps);
}
```

可以看到，新vnode的`el`直接指向旧vnode的`el`。这就是虚拟DOM更新中“复用节点”的第一步。

### 五、props如何更新和删除

`patchProps`分成两个方向：

1. 遍历新props，值不同就更新；
2. 遍历旧props，新props中不存在的就删除。

```ts
function patchProps(el, oldProps, newProps) {
  if (oldProps !== newProps) {
    for (const key in newProps) {
      const prevProp = oldProps[key];
      const nextProp = newProps[key];

      if (prevProp !== nextProp) {
        hostPatchProp(el, key, prevProp, nextProp);
      }
    }

    if (oldProps !== EMPTY_OBJ) {
      for (const key in oldProps) {
        if (!(key in newProps)) {
          hostPatchProp(el, key, oldProps[key], null);
        }
      }
    }
  }
}
```

为什么需要第二次遍历？例如旧节点是：

```ts
h('div', { id: 'app', title: 'hello' });
```

新节点是：

```ts
h('div', { id: 'app' });
```

只遍历新props只能发现`id`没有变化，却发现不了`title`已经被删除。所以更新和删除是两个方向的问题。

### 六、patchChildren处理四种情况

子节点类型变化时，运行时需要根据新旧`shapeFlag`做分支：

| 旧子节点 | 新子节点 | 处理方式 |
| --- | --- | --- |
| 数组 | 文本 | 卸载旧子节点，再设置文本 |
| 文本 | 文本 | 文本变化时更新容器内容 |
| 文本 | 数组 | 清空旧文本，再挂载新数组 |
| 数组 | 数组 | 进入keyed children diff |

代码的核心结构如下：

```ts
function patchChildren(n1, n2, container, parentComponent, anchor) {
  const prevShapeFlag = n1.shapeFlag;
  const c1 = n1.children;
  const { shapeFlag } = n2;
  const c2 = n2.children;

  if (shapeFlag & ShapeFlags.TEXT_CHILDREN) {
    if (prevShapeFlag & ShapeFlags.ARRAY_CHILDREN) {
      unmountChildren(n1.children);
    }
    if (c1 !== c2) {
      hostSetElementText(container, c2);
    }
  } else {
    if (prevShapeFlag & ShapeFlags.TEXT_CHILDREN) {
      hostSetElementText(container, '');
      mountChildren(c2, container, parentComponent, anchor);
    } else {
      patchKeyedChildren(c1, c2, container, parentComponent, anchor);
    }
  }
}
```

这里的核心思想是：先判断新节点是什么，再根据旧节点是什么决定复用、清空、卸载还是进入diff。

### 七、组件更新为什么使用scheduler

如果一个事件中连续修改很多次响应式数据：

```ts
for (let i = 0; i < 100; i++) {
  count.value = i;
}
```

每次修改都立刻执行完整的组件render，会产生很多没有必要的中间状态。于是组件effect提供了`scheduler`：

```ts
{
  scheduler() {
    queueJobs(instance.update);
  }
}
```

这里并没有马上调用runner，而是把runner放到队列里。队列如何去重、什么时候刷新，会在`nextTick和运行时API`一篇中展开。

### end

组件更新的核心并不是“重新生成一棵DOM树”，而是：

```text
复用旧vnode和旧el
       ↓
比较新旧props
       ↓
比较新旧children
       ↓
只修改发生变化的部分
```

当新旧子节点都是数组时，最关键的部分就是下一篇的keyed children diff。
